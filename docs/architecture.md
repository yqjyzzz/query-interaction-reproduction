# 仓库架构与边界

## 双轨结构

仓库将“验证已发表数字”和“运行视觉模型”拆成两个独立问题。

论文复现轨道以冻结的分析就绪数据为起点。它调用归档时保留的聚合程序，生成四组结果，再与冻结结果逐字段比较。这样可以验证统计计算和结果文件，却不会把缺失的原始图像、模型权重或质量矩阵伪装成已公开资源。

视觉检测轨道以本地 COCO 数据和用户提供的 checkpoint 为起点。数据读取器、模型适配层、推理入口、评估模块和可视化模块通过明确的数据契约连接。它产生自己的运行记录，不进入论文证据链。

## 关键契约

| 契约 | 约束 |
|---|---|
| 冻结工件 | 清单内文件必须通过大小与 SHA-256 校验 |
| 论文结果 | 新计算结果必须在 `1e-12` 容差内匹配冻结结果 |
| 模型输出 | 适配层接收查询分类分数与归一化边界框 |
| 统一预测 | 边界框使用像素坐标，包含置信度和类别编号 |
| 类别映射 | 模型类别编号必须显式对齐目标数据集类别编号 |
| 检测评估 | 匹配同时满足类别一致与 IoU 阈值 |
| 运行记录 | 保存输入摘要，不保存本机绝对路径 |
| 目录写入 | 视觉检测轨道不得写入冻结工件目录 |

## 维护原则

1. 论文数字、估计目标或结论变化时，应先更新论文工作流中的证据与审计记录，不能直接改复现输出。
2. 新增模型后端时，应新增适配器或外部构建函数，不应把特定第三方实现耦合进公共推理流程。
3. 新增评估指标时，应说明其匹配规则、聚合单位和适用范围，并通过最小反例测试。
4. 发布前应执行 `python scripts/check_repository.py`，并确认版本控制中不存在权重、私有数据、运行缓存或本机路径。
